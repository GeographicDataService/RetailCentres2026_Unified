# Reproduce Foursquare POI Retrieval

This subproject produces the UK Foursquare POI parquet consumed by
`Boundaries/data/inputs/poi/uk_foursquare_cc_nov_iceberg.parquet`.

The code was adapted from the original `cjber/overture-uk` workflow, but the
current repository no longer uses that DVC pipeline or the census post-processing
stage. The current workflow has two stages:

1. `src/query_foursquare_bycc_iceberg.py` queries Foursquare OS Places via DuckDB
   ICEBERG and writes `data/raw/uk_foursquare_cc_nov_iceberg.gpkg`.
2. `src/clean_foursquare.py` normalises geometry/categories and writes
   `data/processed/uk_foursquare_cc_nov_iceberg.parquet`.

## Setup

Use the unified repository environment from the repo root:

```bash
uv venv --python 3.12
source .venv/bin/activate
uv pip install -e .
```

Then provide a Foursquare ICEBERG token:

```bash
cd Foursquare_POI_retrieval
cp .env.example .env
# edit .env and set FOURSQUARE_ICEBERG_TOKEN
```

Get the token from the "Access via code" / API section of the Foursquare OS
Places dataset page:
`https://places.foursquare.com/dataset/OS%20Places/code`.

## Run

```bash
./run_foursquare.sh
cp data/processed/uk_foursquare_cc_nov_iceberg.parquet \
   ../Boundaries/data/inputs/poi/uk_foursquare_cc_nov_iceberg.parquet
```

## Notes

- The old `requirements.txt` generated by PDM has been replaced by a small
  compatibility file. Prefer the root `pyproject.toml` and `uv.lock`.
- `src/query_foursquare_bycc.py` remains as a fallback for local parquet dumps;
  it is not used by `run_foursquare.sh`.
- Intermediate and output files under `data/` are gitignored.
